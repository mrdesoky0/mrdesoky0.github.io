Privacy Policy

desoky — personal Gmail integration · Last updated 21 September 2026

This policy describes how the desoky application ("the Application") accesses, uses, stores, and shares information obtained from Google APIs. The Application is a private, single-user tool operated by one individual against their own Google Account.

1. Google user data we access

With the account owner's explicit consent, the Application requests these scopes:

  • gmail.modify — read, compose, send, and organise messages; manage labels and read/unread state
  • gmail.settings.basic — read and manage basic mailbox settings such as filters

Access is limited to the single Google Account that granted consent. The Application cannot access any other Google Account.

2. How we use the data

Data is used solely to perform actions the account owner explicitly requests through their own local AI assistant — for example, reading a message, searching the mailbox, or sending a reply. The data is never used for advertising, profiling, analytics, model training, or any purpose other than carrying out the owner's direct instructions.

3. How we store and protect the data

  • OAuth credentials (access and refresh tokens) are stored locally on the owner's own devices, in a directory readable only by the owner's user account (filesystem permissions 0600).
  • Message content is processed in memory to fulfil a request. It is not written to any database, and it is not retained after the request completes.
  • Credentials are never committed to source control and are excluded from any code repository.

4. Sharing and disclosure

We do not share, sell, transfer, or disclose Google user data to any third party. Specifically:

  • No third-party servers, cloud services, or intermediaries receive Google user data.
  • No analytics, telemetry, advertising, or tracking services are used.
  • Data is not transferred to any party for advertising, marketing, or creditworthiness purposes.
  • The Application's use of Google user data complies with the Google API Services User Data Policy, including its Limited Use requirements.

5. Retention and deletion

Locally stored OAuth tokens remain until the owner deletes them. The owner may revoke the Application's access to their Google Account at any time, which immediately invalidates the stored tokens:

  • Visit myaccount.google.com/permissions, select the Application, and choose Remove access.
  • Then delete the local credential files from the owner's devices.

Because message content is not persisted by the Application, revoking access leaves no remaining copy in the Application's control.

6. Children's privacy

The Application is not directed at children and is not made available to any person other than its single operator.

7. Changes to this policy

Any material change to this policy will be published on this page with an updated revision date.
